Identity & age

No username signup. Each witness is an auto-minted ed25519 key with a display label like kairos-a3f1b2 (derived from the pubkey). The contract only stores node_id = bs58(pubkey).

Where the secret lives

  1. Preferred: Freenet delegate kairos-identity — EnsureIdentity / SignPulse / SignStampObserve. Secret stays on the node.
  2. Fallback: durable local key (memory + shared window.name bag + localStorage when allowed) for Freenet sandbox pages where storage is restricted.

If the secret is wiped, a new key is minted. Roster age for that key starts over (intentional Sybil cost). If a delegate-backed session loses its delegate, signing fails closed rather than silently signing one observation with a different browser key; this keeps one operation from appearing under two witness identities.

Age gating

To observe stamps (help seal), a key must have been on the Kairos roster for about one hour (last_seen − first_seen ≥ MIN_AGE_MS). Same rule for everyone.

  • Pulsing itself has no hourly rate limit.
  • Age gating is not “one stamp per hour” — it is “key must be old enough before its observe counts.”
  • Roster / eligible counts on Telemetry metrics show how many keys meet that bar.

Seal-history reputation

Roster rows also track seals_included and seals_outlier — how often this key survived MAD into a sealed stamp vs was dropped as an outlier. After a few seals exist network-wide, keys below a reputation floor cannot observe stamps; surviving observes are weighted (age × reputation) into the seal median.

  • New keys start neutral (cold start).
  • Score is not “agree with the live pulse median” — that would let a Sybil flood exile honest peers.
  • Full trust map: Trust & security.

Telemetry list

Each pulse row shows the auto name, a pubkey preview (click to copy), and agreement with the pulse median (bar length). Your row is tagged (you). Sealed stamps have a separate Seal witnesses table (request id → witness_ids).
