API surfaces

Contract updates are small JSON deltas over Freenet Update. Reads are Get / Subscribe on the Kairos contract key. Signing prefers the kairos-identity delegate. If the session starts with the delegate, a later signing failure stops that operation instead of silently switching to the browser fallback key.

1. Pulse (write)

{
{ "pulse": {
    "node_id": "<bs58 ed25519 vk>",
    "wall_ms": 0,
    "monotonic_ms": 0,
    "uncertainty_ms": 40,
    "sig": "<hex>"
} }

Domain kairos.pulse.v1. Keeps the contract hosted and ages the roster. Site helper: submitPulse() (delegate sign + Update). The OTP page pulses first, then reads — its Get buttons send a pulse before fetching so the median includes your fresh observation.

2. Open stamp (write)

{
{ "open_stamp": { "content_hash": "…", "nonce": "unique-per-request" } }

Creates open_stamps["hash:nonce"]. Anyone can open; only aged keys’ observes count toward seal.

3. Observe stamp (write)

{
{ "observe_stamp": {
    "request_id": "hash:nonce",
    "observation": { /* same fields as pulse, domain kairos.stamp.observe.v1 */ }
} }

Rejected if the witness is younger than ~1 hour on the roster. When ≥ min witnesses survive MAD, the request moves to sealed_stamps.

4. Get / Subscribe (read)

Get the contract; inspect pulse / roster / sealed_stamps. With subscribe: true, the gateway pushes UpdateNotification on later Updates — apps re-Get or apply deltas then. See Get & Subscribe.

5. Identity delegate (local)

EnsureIdentity, SignPulse, SignStampObserve (optional Export/Import). Auto-mints a label like kairos-a3f1…. If the delegate is unavailable, the site falls back to a durable browser key during initial identity bootstrap. Once a backend is selected, signing stays on that backend: a delegate outage fails closed instead of mixing witness identities. See Identity & age.

6. Network duty (one call — help the oracle)

Separate pulse / observe / Get APIs stay available. For public-goods hosting, apps can use one duty surface that decides what to do from roster age + open stamps — over the same Freenet WebSocket (not a new HTTP endpoint).

  • queryNetworkDuty() — Get + return a plan (no writes).
  • runNetworkDuty() — execute the plan: always pulse (keep-alive / age); if stamp-eligible (~1h), also observe_stamp any open requests you have not signed.
  • watchNetworkDuty() — Subscribe + interval: keep running duty automatically while your app is open.
  • planNetworkDuty(state, identity) — pure helper if you already have state. 
{
// plan shape (kairos.network.duty.v1)
{
  "schema": "kairos.network.duty.v1",
  "stamp_eligible": false,
  "roster_age_ms": 0,
  "min_age_ms": 3600000,
  "open_count": 0,
  "actions": [
    { "type": "pulse", "reason": "…" },
    { "type": "observe_stamp", "request_id": "hash:nonce", "reason": "…" }
  ],
  "summary": "pulse · aging …"
}

The Telemetry page starts bounded duty automatically; there is no manual Pulse or Refresh control. “Get only” uses queryNetworkDuty() so you can see what help would look like without writing.

Soft Kairos time for Tyche

The Tyche client can read an aged Kairos pulse median as a client-side coordination hint. It reports the source and confidence, retains a last-known verified value through short gateway failures, retries with backoff, and eventually labels a local-clock fallback. This never replaces signed Tyche timestamps or turns Kairos into a hard cross-contract dependency.

Dual public-good duty

The Kairos site also runs Tyche’s bounded watchTycheDuty() beside its own watchNetworkDuty(). This is deliberately two independent witnesses: Kairos uses its Kairos identity and contract; Tyche uses its Tyche identity and contract. The coordinator only pulses and contributes to existing eligible work — it never opens or closes a Tyche round, opens recovery, or changes either protocol. Apps can use the same pattern when they want one Freenet service to soft-host both public goods.

Client checklist (app author)

  1. Ensure Kairos contract exists (Put once / Get).
  2. Ensure identity (delegate or local).
  3. Prefer watchNetworkDuty() or runNetworkDuty() on an interval while open — one call covers keep-alive and seal help.
  4. Continuous clock: Subscribe + hardened pulse tip (OTP pattern) — not raw public median. Limits: Trust & security.
  5. Authoritative time for a hash: open → wait for seal → Get sealed entry → build notary receipt.
