Trust & security

Kairos is the production shared clock — early, still hardening. The threat model is not finished MFA or a Byzantine clock. This page is the honest map: what the contract actually resists, and what still fails under a determined flood.

Where strength is

  • Sealed stamps — notarize surface. Needs ≥5 distinct aged keys after MAD. One peer cannot fill five slots. Median + error_ms / [earliest, latest] + transcript_digest + witness_ids are Get-able and portable (see Notary receipts).
  • Age gate — stamp observes require ~1h on the roster (MIN_AGE_MS). Fresh Sybil keys cannot seal immediately.
  • Seal-history reputation — after a few network seals exist, stamp eligibility and observe weights use how often a key was included vs MAD-dropped at seal (seals_included / seals_outlier). New keys start neutral. Score is not “agree with the live pulse median” — that would let a Sybil flood exile honest peers.
  • Weighted seal median — among MAD survivors, wall times are weighted by age ramp × reputation (older, cleaner seal history pulls harder).
  • Signatures — pulses and observes are ed25519 over fixed domains. Roster identity is the pubkey.
  • Get is read-only — reading state does not write pulses or votes.

Where it isn’t

  • Raw public pulse median — anyone can pulse. A Sybil cloud of fresh keys can yank the client-side median of pulse. Telemetry’s “Median pulse” is that surface: useful telemetry, not a notary.
  • OTP lab (early MFA surface) — TOTP over a hardened tip (aged + reputation-weighted pulses, min-n, jump hold). Better than raw median, still not finished MFA: shared secret must stay secret; young networks fall back to bootstrap; an adversary who can age many keys still matters. See OTP.
  • Young / thin networks — reputation gate waits until a few seals exist; OTP tip bootstraps when too few aged pulses. Example stamps will not seal until ≥5 distinct aged peers observe. Empty sealed_stamps is normal — do not invent a seal from the pulse map.
  • Device / NTP sync — Kairos never steers laptop clocks. Apps Get intervals and widen error with local staleness.
  • Identity = human trust — keys are auto-minted. Age and seal history are Sybil friction, not KYC or GitForge linkage.
  • Bounded state — roster / pulse / seal maps are capped. Floods get pruned; they do not prove honesty of whoever remains.

Reputation (seal history only)

Each roster entry tracks seals_included and seals_outlier. Score is blended toward neutral until there is a short history, then tracks include-rate (0–1000 scale). Once the network has a few seals, keys below a floor cannot observe stamps; surviving observes are weighted into the seal median.

Reputation must stay tied to past seals, never to agreement with the live pulse majority. Live-majority reputation is an exile attack.

Which surface for which risk

  • Portable “this hash around this interval” — sealed stamp + receipt. Strongest Kairos claim today.
  • Continuous lab clock / OTP digits — hardened pulse tip. Early; document the limits to users.
  • Hosting / keep-alive — pulse freely; do not treat pulse median as notarize truth.

Public goods (when this actually works)

Seals, reputation, and a trustworthy tip only become real once other Freenet apps and services wire Kairos into their frameworks — Subscribe / soft-Get the contract, run network duty (pulse, observe open stamps when eligible), and keep the oracle warm while their users are online. People using those apps then contribute to the shared good without a separate “go host Kairos” chore.

Freenet does not magically keep unrelated contracts alive. As a network, shared services like this only stay reachable if apps put time and energy into maintaining them — reciprocity is client policy, not WASM magic. Kairos should soft-host a small public-goods set in return (see Hosting and repo docs/public-goods.md).

The sibling public good is Tyche (auditable randomness). This site runs bounded watchTycheDuty() beside its own duty, and Tyche's site mirrors that for Kairos — each using the service's own identity, so the two trust domains never merge. Both publish the standardized freenet.public-good.v1 manifest (service-owned identity, key held by the service delegate, foreground EnsureIdentity only); see repo docs/public-goods.md and Hosting.

Alone on one tab, the network stays thin. Embedded across Freenet apps (GitForge already runs network duty in the background), Kairos is a shared clock the mesh can actually use — start integrating now.
