Notary receipts

A receipt is portable JSON: “this content hash was sealed in [earliest, latest] by these witnesses, with this transcript digest” — backed by a Freenet Get of sealed_stamps.

How to obtain one

  1. Your app calls open_stamp({ content_hash, nonce }) → request_id = hash:nonce. Telemetry does not invent opens — only apps with real content to notarize should.
  2. Age- and reputation-eligible peers each observe_stamp once (one row per node_id). Network duty / Telemetry will help if open requests exist.
  3. After ≥5 distinct eligible observes (MAD-filtered), the contract seals a weighted median + interval + transcript and updates seal-history reputation. More than five observes is allowed before seal; after seal, further observes are ignored.
  4. Get Kairos; read sealed_stamps[request_id]; export buildNotaryReceipt(…).

Receipt fields (v1)

{
{
  "schema": "kairos.notary.receipt.v1",
  "request_id": "hash:nonce",
  "contract_key": "…",
  "content_hash": "…",
  "median_wall_ms": 0,
  "error_ms": 0,
  "earliest_ms": 0,
  "latest_ms": 0,
  "witness_count": 0,
  "witness_ids": [],
  "transcript_digest": "…",
  "sealed_at_ms": 0
}

Using a receipt later

  • Re-Get the contract (or keep a snapshot) and check the sealed entry still matches the transcript / interval.
  • Widen error_ms with local age since Get (effectiveErrorMs) — do not treat a stale Get as tight as a fresh seal.
  • “Not before / not after” helpers: assertNotBefore / assertNotAfter.
Pulses alone never produce a notary receipt. If sealed_stamps is empty, there is nothing to notarize yet — only keep-alive telemetry. The offline Demo page is gone; wire parsers against this schema or a real sealed Get.
